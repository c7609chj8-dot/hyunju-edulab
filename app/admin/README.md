# 관리자 센터

## 경로

- `/admin/login`: 관리자 이메일·비밀번호 로그인.
- `/admin`: 전체·활성·이용 정지 회원 현황.
- `/admin/members`: 이름·회원 아이디·이메일 검색, 25명 단위 목록.
- `/admin/members/[id]`: 회원 정보 수정, 이용 정지·복구, 최근 변경 기록.

## 인증과 저장

- 현재 DB: `ai-education-hub-dev` (`uenvjqgylrevujdjpfed`, 일본 도쿄).
- `(protected)` 폴더는 URL에 포함되지 않는다. 레이아웃·각 페이지·저장 Server Action에서 `administrationAccess()`로 인증과 활성 관리자 권한을 확인한다.
- DB RLS는 본인 또는 활성 관리자만 조회하도록 제한한다. 수정은 활성 관리자만 가능하며 수정 가능 컬럼도 제한한다.
- `membership_private.is_active_administrator()`는 사용자 메타데이터를 신뢰하지 않고 현재 Auth 사용자·관리자 역할·회원 이용 상태를 검사한다.
- `revision`이 변경되면 이전 화면에서의 저장을 거부한다. 수정 항목명과 이전·다음 상태를 감사 테이블에 기록하며 주소·전화번호 원문은 감사 로그에 복사하지 않는다.
- 활성 관리자 계정의 이용 정지는 차단한다. 일반 회원 정지는 이 홈페이지 이용에 적용되며, 공유 Supabase 프로젝트의 다른 앱 인증 계정을 정지하거나 삭제하지 않는다.
- 계정 삭제·관리자 권한 부여/회수는 Supabase 콘솔에서 별도로 처리한다. 비밀번호 원문을 조회하는 기능은 없다.
- 기존 인증된 관리자 계정의 기본 프로필을 연결했다. 기존 가입에 대해 새 개인정보 동의 시각을 만들어 넣지 않았다. 다른 앱의 기존 Auth 계정은 자동으로 회원 목록에 가져오지 않는다.
- 신규 가입은 `membership_app=hyunju-edulab` 메타데이터와 현재 동의 버전을 검증하여 프로필을 생성한다.

## 검증

- `npm run verify`: 입력 검증·검색·수정 검증, lint, 빌드, 타입 검사.
- `supabase/tests/admin_management.sql`: 실제 DB에서 수정·감사·동시 수정 충돌·정지/복구·관리자 보호·권한 회수·익명 차단을 확인하고 전체 롤백한다.
- 저장소의 마이그레이션 파일은 이 회원 기능의 변경을 기록한다. 공유 DB에 원래 있던 교육 기능 스키마와 마이그레이션은 별도 범위이며 유지한다.
- 임시 계정을 DB에 남기는 로그인 시험은 해당 프로젝트에 대한 별도 승인이 필요하다. 실제 관리자의 비밀번호는 당사자가 입력한다.
