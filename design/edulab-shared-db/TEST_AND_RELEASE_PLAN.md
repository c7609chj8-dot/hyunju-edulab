# 승인·테스트·백업·적용·롤백 계획

## 현재 상태와 금지 범위

현재는 설계 단계다. 이번 작업에서 수행한 것은 소스 읽기, Supabase 메타데이터 조회, 별도 설계 파일 작성과 정적 검토다. 아래 테스트·SQL·키 설정·관리자 지정·배포는 **계획이며 실행 결과가 아니다**.

- 새 Supabase 프로젝트를 만들지 않는다. 현재 프로젝트는 이름과 무관하게 Production으로 취급한다.
- 기존 `member_profiles`, `member_administrators`, `published_courses` 및 다른 테이블·뷰·데이터·함수·정책·트리거·Auth 설정을 변경하지 않는다.
- 기존 범용 테스트 마이그레이션을 `db push`로 일괄 실행하지 않는다.
- `main`에 병합하지 않고 운영 배포·환경변수·기능 플래그를 변경하지 않는다.
- Production에 임시 계정·문의·관리자·시험 데이터를 만들거나 삭제하지 않는다.

## 1. 승인 전 정적 검토

| 확인 항목 | 합격 기준 |
|---|---|
| 브랜치·파일 | 지정 소스 커밋에서 별도 브랜치, 변경 파일이 `design/edulab-shared-db/` 아래뿐 |
| 운영 SQL 실행 | `execute_sql`, `apply_migration`, `db push`, `db reset`, Auth 데이터 변경 호출 없음 |
| 객체 이름 | 새 공개 테이블 3개만 `edulab_`로 시작. 새 함수도 edulab 이름, 비공개 스키마 분리 |
| 기존 객체 보호 | 기존 객체 대상 ALTER·GRANT·REVOKE·TRIGGER·UPDATE·DELETE·DROP 없음. 기존 관리자 복사 SQL 없음 |
| 생성 SQL | DROP·TRUNCATE 없음. DELETE 문 없음. UPDATE는 새 상태 함수의 PK+revision 조건 한 곳뿐 |
| 이름 충돌 | CREATE OR REPLACE/CREATE IF NOT EXISTS 없음. 충돌 시 중단 |
| 공개 쓰기 | anon/authenticated INSERT 권한 없음, 접수 RPC는 service_role만 실행 |
| 관리자 쓰기 | 직접 UPDATE 권한 없음, JWT 사용자 전용 RPC에서만 상태·이력 동시 변경 |
| 비밀·개인정보 | 실제 키·비밀번호·연락처·회원 UUID·DB 행 데이터가 파일에 없음 |

파일 공백 검사는 수행하지만, SQL을 운영 DB에 컴파일하거나 실행했다고 보고하지 않는다. 앱 코드는 변경하지 않으므로 기존 Next.js 빌드를 다시 돌려 DB SQL 검증으로 대체하지 않는다.

이번 정적 확인에서는 Node의 파일 읽기와 assertion만으로 문서 내부 링크, 정확히 3개 전용 테이블, 새 테이블만 대상으로 한 ALTER, 생성 SQL의 파괴적 실행문 부재, 조건부 상태 UPDATE, 공개 함수의 INVOKER 모드, 승인 토큰과 RESTRICT가 있는 롤백을 검사해 PASS를 확인했다. 이는 PostgreSQL 파서나 DB 동작 시험이 아니다.

## 2. 적용 전 추가로 필요한 읽기 전용 확인

현재 Supabase 메타데이터 도구로 열·키·RLS는 확인했지만 뷰·기존 GRANT·기본 권한·이벤트 트리거 전체는 미확인이다. [읽기 전용 카탈로그 SQL](sql/preflight_readonly.sql)을 별도 승인 후 실행하여 아래를 확인한다.

- `published_courses`의 실제 스키마와 테이블/뷰 종류·정의·기존 권한
- 새 테이블·함수·스키마 이름 충돌, 공개 스키마 기본 권한
- 새 테이블 생성 시 자동으로 동작할 기존 이벤트 트리거의 대상과 부수 효과
- 읽기 전용 기준값: 보호 대상의 구조·권한·행 수 및 필요한 경우 개인정보를 출력하지 않는 데이터 지문
- 프로젝트 Ref, Production 연결, 복원 가능한 백업 시각, API 스키마 노출 설정

예상과 다른 기존 구조가 있으면 그대로 중단하고 설계를 수정한다. 미확인 문제를 기존 테이블 수정으로 해결하지 않는다. 변경이 필요한 다른 서비스의 설정은 이 승인 범위에 포함하지 않는다.

## 3. 별도 승인된 로컬 통합시험

새 Supabase 클라우드 프로젝트는 생성하지 않는다. SQL 실행 허가를 받은 뒤 로컬 Supabase/Postgres에서 필요한 Auth 최소 구조와 가짜 계정을 사용한다. Production 덤프나 실제 개인정보를 복제하지 않는다. 테스트 프레임워크·로컬 런타임 설치도 이번 작업에서는 하지 않았다.

| 시험 | 기대 결과 |
|---|---|
| 생성 SQL 첫 실행 | 새 객체만 생성, 3개 테이블 RLS 활성, 관리자 초기 행 0건 |
| 같은 SQL 재실행 | 이름 충돌로 실패, 기존 구조·데이터 유지 |
| anon/일반 회원의 테이블 접근 | anon 권한 거절, 일반 회원 문의·이력 결과 없음 |
| 기존 member_administrators만 가진 사용자 | 전용 지정 없으므로 문의·이력 결과 없음, 상태 RPC 403 |
| private_education 관리자만 가진 사용자 | 동일하게 차단 |
| user_metadata.role=administrator 위조 | 접근 불가 |
| edulab_admins 자기 지정·활성화 시도 | INSERT/UPDATE/DELETE 권한 거절 |
| 활성 전용 관리자 + 이메일 인증 + 유효 세션 | 본 서비스 문의·이력만 조회 |
| 비활성·revoked_at 설정·Auth 정지·미인증·익명 | 조회 결과 없음, 상태 변경 거절 |
| 삭제·만료·다른 사용자 소유 session_id | 접근 거절 |
| 관리자 역할 회수 후 다음 요청 | 이전 JWT가 남아 있어도 차단 |
| 쿠키 없는 관리자 API·위조 actor 입력 | 401/403, actor 입력 무시가 아니라 계약에서 제외 |
| 관리자 Origin 누락·불일치, CSRF 시도 | 거절, 상태·이력 변화 없음 |
| 허용된 received→reviewing→answered | 상태·revision·이력이 함께 변경 |
| 상태 반복·역행·누락·알 수 없는 상태 | 반복은 no-op, 잘못된 전이는 거절 |
| 두 관리자의 동시 동일 revision 변경 | 한 건 성공, 다른 건 충돌. 중복 이력 없음 |
| 상태 변경 중 관리자 권한 회수 | 전용 행 잠금으로 직렬화, 회수 이후 요청 거절 |
| 강제 이력 INSERT 실패 | 문의 상태 변경도 롤백 |
| 공개 폼 정상 입력 | 201, 문의 1건·최초 이력 1건, 공개 응답에 개인정보 없음 |
| 동의 없음·false·문자열 true·과거 정책 | 거절, 저장 0건 |
| 클라이언트가 조작한 ID·상태·시각·보관일수 | API 거절/서버 허용 필드만 사용, DB 신뢰값으로 생성 |
| 빈값·공백·최대 길이 경계·잘못된 연락처/이메일 | 서버·DB 계약대로 거절, SQL 오류 원문 비노출 |
| Content-Length 없음/거짓, 큰 스트림 | 12,000바이트 초과 중단, 413, 저장 없음 |
| 잘못된 Content-Type·JSON 배열·파일·잘못된 JSON | 400/415, 저장 없음 |
| 허니팟·챌린지 실패·다중 인스턴스 요청 과다 | 400/429 등 거절, DB 저장 없음 |
| 공유 제한/봇 서비스 장애 | 503 등 fail closed, 저장 없음 |
| 같은 키·같은 내용의 동시 재시도 | 문의·접수 이력 각각 1건, 같은 접수번호 재응답 |
| 같은 키·다른 내용 | 409, 이전 내용·접수정보 변경 없음 |
| 다른 키의 접수번호 충돌 | 제한 재시도, 무한 루프·중복 문의 없음 |
| DB 응답 전 연결 단절 후 재시도 | 키 유지, 중복 저장 없음 |
| 서비스 키로 관리자 상태 RPC/관리자 명부 수정 | 권한 거절. 서비스 키의 문의 조회 가능성은 격리 한계로 별도 확인 |
| 보관 만료일 | 확정 일수·UTC 계산 일치. 생성 SQL이 자동 파기 작업을 만들지 않음 |
| 보호 대상 스냅샷 전후 비교 | 기존 구조·권한·데이터 지문 변화 없음 |

정상 작동뿐 아니라 권한이 없는 계정의 차단 결과를 필수 증거로 남긴다. 실제 UUID·본문·인증 토큰은 공개 테스트 로그나 Git에 포함하지 않는다.

## 4. 백업과 안전한 Production 적용

1. 백업 파일만 있다고 복원 가능하다고 단정하지 않는다. 최근 정상 백업의 시각·보관 범위와 복원 절차를 확인한다.
2. 필요한 경우 공식 CLI 절차로 역할·스키마·데이터를 따로 내보내고 Auth 데이터·정책·함수·뷰의 포함 범위를 점검한다. 비밀 접속 문자열·백업 파일은 저장소/공개 폴더에 넣지 않는다.
3. Storage 실제 파일과 Auth 제공자·SMTP 등 프로젝트 설정은 DB 덤프와 별도 범위다. 전체 프로젝트 복원은 다른 홈페이지 데이터도 과거로 돌릴 수 있어 일상적인 롤백 수단으로 사용하지 않는다.
4. 로컬 시험 후 승인된 정확한 생성 SQL 하나만 적용한다. 생성 SQL의 함수 본문 외부에는 데이터 쓰기가 없고 관리자 seed도 없다. 기존 마이그레이션을 다시 적용하지 않는다.
5. 2초 lock timeout·30초 statement timeout을 사용한다. FK나 DDL 잠금으로 대기하면 기존 잠금을 강제 해제하거나 제한을 무작정 늘리지 않고 중단·재검토한다.
6. 새 객체 이름·함수 보안 모드·RLS·명시적 GRANT·전용 관리자 빈 상태를 확인한다. 보안 점검기를 실행하고 신규 경고를 기존 프로젝트 경고와 구분한다.
7. 보호 대상 기준값과 비교한다. 다른 서비스의 정상 동시 변경이 있을 수 있어 차이가 나면 원인을 확인한 뒤 다음 단계로 진행한다.
8. 관리자 등록·실제 문의 저장·메일 발송·삭제 시험은 각각 허가된 범위 안에서만 한다. 승인된 생성 SQL 적용만으로 실데이터 시험 승인을 추정하지 않는다.
9. 공개 전까지 접수·알림 플래그는 false를 유지한다. 확정 보관기한의 점검·파기 담당과 절차도 별도로 승인하고 검증해야 한다. 이번 생성 SQL은 파기 스케줄을 만들지 않으며, 만료일 열만 있다고 파기가 완료되는 것은 아니다. Preview가 같은 Production DB를 사용해도 시험 DB로 취급하지 않는다.

## 5. 데이터 손실 없는 롤백 우선순위

### A. 기본안: 기능만 중단하고 데이터 보존

오류 시 우선 새 접수·상태 변경 기능을 끄고, 승인된 코드 버전으로 되돌린다. `edulab_` 테이블과 문의 데이터는 유지한다. 필요한 경우 새 전용 함수 권한만 제한하는 별도 최소 SQL을 검토·승인받는다. 기존 회원·교육 기능을 복구 대상으로 덮어쓰지 않는다.

### B. 새 테이블 3개가 모두 비어 있는 경우에만 구조 제거

[rollback_empty_only.sql](sql/rollback_empty_only.sql)은 **검토용이며 실행하지 않았다**.

- 별도 롤백 승인과 트랜잭션 내부 승인 토큰이 없으면 시작부터 중단한다.
- 새 기능의 트래픽을 먼저 중단한다.
- 새 테이블 3개만 잠그고 데이터 존재 여부를 확인한다. 문의·이력·관리자 중 한 행이라도 있으면 예외로 중단한다. 관리자 지정이 끝났어도 자동으로 지우지 않는다.
- DROP은 새 공개 함수 2개·새 테이블 3개·새 비공개 함수 2개·새 비공개 스키마에만 적용한다.
- 모든 DROP에 RESTRICT를 사용한다. `DROP ... CASCADE`, DELETE, TRUNCATE, 기존 객체 대상 DROP, 마이그레이션 이력 삭제는 없다.
- 예상하지 못한 의존성이 있으면 전체 트랜잭션이 실패한다. 실패 시 COMMIT하거나 일부 구문만 재실행하지 않는다.
- 실행 시에는 별도 롤백 마이그레이션으로 이력을 남긴다. 기존 `supabase_migrations.schema_migrations` 행을 삭제하지 않는다.

### C. 데이터가 있는 경우

자동 구조 제거·초기화 SQL을 제공하지 않는다. 문의·동의·이력·관리자 기록을 보존한 상태에서 원인과 보관 의무를 확인하고, 복구 시험과 별도 최종 승인을 받은 데이터 이전/복구 계획을 작성한다. 이 경우 테이블 삭제보다 코드 복구·기능 차단이 기본 선택이다.

## 6. 이번 결과물에서 검증한 것과 남은 것

| 수행 | 상태 |
|---|---|
| 지정 브랜치 소스와 DB 테이블 메타데이터 분석 | 수행 |
| main/운영 코드·설정 변경 없이 별도 설계 작성 | 수행 |
| 생성 SQL 영향 범위·관리자 분리·기본 권한·롤백 조건 정적 검토 | 수행 |
| SQL 파서/DB 컴파일·로컬 통합시험 | 미실시 |
| Production SQL 실행·스키마 변경·신규 계정/데이터 생성·삭제 | 미실시 |
| 뷰 정의·기본 GRANT·이벤트 트리거의 카탈로그 SQL 조회 | 미실시, 별도 승인 후 확인 |
| 실제 배포·공개 접수·관리자 권한 지정 | 미실시 |
